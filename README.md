# 短剧评估法条本 · Short-Drama Evaluation Codex

**一本带编号的判据集，用来评估短剧的点子、剧本、分镜和商业适配。**

不是评分表，不是一键打回器。它把"我觉得这稿不行"换成

> 「这条违反了 `IP-04`，判据是量级两条轴都悬在中间，出处是 `24 N4`。」

- **120 条规则**，8 个域，每条都有编号、判据、反例／边界、出处、强度
- **机器可读**：规则正本是一个 TSV，附一个零依赖检索器
- **可引用**：评估单里引编号，不引感觉；`check_eval.py` 会校验编号是否真实存在
- **自带反例**：这一域最大的坑不是判据不够多，是把评估做成了闸门

## 为什么需要它

去 GitHub 上找"短剧评估"，能拿到的基本都是**规则清单**：给你 37 条判据去挑刺。

问题不在条数。真实事故是这样发生的：一夜 18 次返工、8.4M token、**0 张可读样本**，
25 个项目被自己写的 8 处硬停掐死——而事后拿 127 集真剧做召回测试，
那些"检测器"的召回率是 **0.0% / 0.8%**。

> 失败的不是某个模块，是「审美可以被编译成约束」这个前提。

所以这本法条本把两件事分开：**判据**（`IP`–`BIZ` 七个域）和**评估纪律**（`MET` 域）。
后者规定了怎么用前者：不做闸门、不给总分、事实与解释分层、闸门必须报召回率。

## 安装

### 作为 Agent Skills 技能（Claude Code / pi / 其他兼容实现）

放到任一技能目录即可，目录名要与 `SKILL.md` 的 `name` 一致：

```bash
# 用户级（所有项目可用）
git clone <this-repo> ~/.agents/skills/short-drama-eval-codex

# 或 pi 的用户技能目录
git clone <this-repo> ~/.pi/agent/skills/short-drama-eval-codex

# 或项目级
git clone <this-repo> .agents/skills/short-drama-eval-codex
```

装完用 `/skill:short-drama-eval-codex` 可直接强制加载。

### 只想当文档读

不需要安装任何东西。`references/` 是纯 markdown，`data/rules.tsv` 可以用任何表格工具打开。

### 依赖

- 纯文本，无第三方依赖
- 脚本需要 Python 3.8+（只用标准库，不联网）
- Windows 上把命令里的 `python3` 换成 `python`

## 快速开始

```bash
# 1. 体检规则文件本身
python3 scripts/xr.py selftest
python3 scripts/xr.py check

# 2. 看有哪些域
python3 scripts/xr.py domains

# 3. 取某个域的规则（只取硬规则）
python3 scripts/xr.py domain IP --hard

# 4. 看一条规则的全文
python3 scripts/xr.py show IP-04

# 5. 按问题搜
python3 scripts/xr.py search 对白
python3 scripts/xr.py search 量级 --domain IP

# 6. 导出给别的程序
python3 scripts/xr.py export --json > rules.json
```

评估一份稿子的顺序：

1. 读 `references/08_评估方法学.md`（不读这个，后面都会用错方向）
2. 按对象阶段选域（对照 `SKILL.md` 第 1 步的表）
3. 用 `templates/评估单模板.md` 填：**事实层 → 命中清单 → 判断层 → 裁决**
4. 用 `scripts/check_eval.py 评估单.md` 体检形式
5. 交付"分档 + 条件 + 升档路径"，不给总分

## 规则一览

| 前缀 | 域 | 条数 | 其中硬规则 |
|---|---|---|---|
| `IP` | 选题与点子 | 24 | 18 |
| `HOOK` | 爽点与兑现 | 15 | 12 |
| `STR` | 结构与节奏 | 13 | 8 |
| `CHR` | 人物与关系 | 9 | 6 |
| `DIA` | 对白 | 16 | 13 |
| `VIS` | 视听与镜头 | 18 | 13 |
| `BIZ` | 商业与合规 | 9 | 6 |
| `MET` | 评估方法学 | 16 | 16 |
| — | **合计** | **120** | **92** |

**强度**：`硬`＝结构性死症，命中就要认真处理；`中`＝有条件的口味问题；`软`＝默认值／偏好，可被项目覆盖。

## 不要这样用

| ❌ | 为什么 | 对应规则 |
|---|---|---|
| 批量注入写手提示词当"必须遵守" | 同一批判据，创作前用＝检查表，注入提示词＝禁令，效果相反 | `MET-03`、`MET-16` |
| 让正则／脚本自动判死 | 没测召回率的检测器是指纹库 | `MET-01`、`MET-08` |
| 用总分排序候选剧本 | 实测多模型平均分会把你 Kill 掉的排进前三 | `MET-09`、`MET-10` |
| 拿旧平台清单当现行口径 | 红线和定价都会过期 | `BIZ-05` |
| 声称"经本体系认证" | 授权条款禁止背书性表述 | `LICENSE` 第五节 |

## 适用边界（重要）

这本法条本**有明确的口径与边界**，`references/09_来源与出处.md` 有逐组说明。最要紧的三条：

1. **爽剧口径。** `IP-01`、`IP-10`、`IP-15`、`HOOK-*`、`CHR-01~04` 来自男频轻爽／爽剧实践。
   写文艺片、正剧、悲剧必须重估；`CHR-03`（主角不带弱点）在正剧里**明确不适用**。
2. **参数会过期。** `VIS-16~18`、`BIZ-*` 里的数值、价格、平台红线是某一时点的记录，
   不是标准。超过半年请重新核实。
3. **`MET` 只管创作型产线。** 在合规审查、法务、平台审核场景里，"闸门"是正当的，
   不要把这套反闸门原则搬过去。

## 贡献

欢迎提 issue / PR，但请守住两条：

1. **不要新增没有出处的判据。** 每条规则必须能追到一次真实复盘、一份规范或一组实验；
   本仓库宁可少，不可编。
2. **不要把它往闸门方向改。** 任何让脚本"自动判死一份稿子"的 PR 都会被拒（`MET-01`）。

新增规则前先读 `references/09_来源与出处.md` 第二节的引用纪律。
