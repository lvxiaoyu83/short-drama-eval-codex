# 06 · 视听与镜头（VIS）

18 条。管的是**能不能拍出来、能不能一次过**。

规则正本：`data/rules.tsv`（`python3 scripts/xr.py domain VIS`）。

## 一、最先看这一条：三米外可见（VIS-01）

`VIS-01` 其实是从剧本层掉下来的镜头判据，也是本库里最常被引用的一条：

> **决定胜负的那个东西，要能在三米外看见。**

城门开没开、旗倒没倒、天裂合没合。这句追问的对象**不是主角的弱点**
（那是 `CHR-03` 禁止的东西），而是**这场戏的赌注**。

它同时否掉一整类写法：把胜负放在落款位置、笔锋走向、螺丝圈数、绳结方向上。
摄影机拍不到，观众也不会为此屏息。

## 二、空间与方向（VIS-02 ~ VIS-04）

- **双人对白写清视线、位置和反打关系。**
- **依赖路线的动作要让观众看懂起点与落点**：追逐、抢夺、开门——不把所有镜头都切成无方向的人脸。
- **复杂空间先试少量镜头**，根据实际结果简化或补参考图，再决定全面铺开。

## 三、动态剧不等于静图推拉（VIS-05）

正式 AI 动态剧用视频模型出镜头，**不用 ffmpeg 静图推拉充当动态表演**。
解说漫的静图运镜是另一套做法，不要混用。

## 四、提示词的六项硬要求

| 编号 | 要求 |
|---|---|
| VIS-06 | 开头声明：图片或视频、画幅、分辨率、总时长；接口参数与正文一致 |
| VIS-07 | 画面中的人逐个点名，带外形、当前服装和位置；不用资产编号代替人物 |
| VIS-08 | 参考图默认场景在前，角色按首次出场或开口顺序；正文、实际附件数组、人读清单三处顺序一致，并写明每张图锁什么 |
| VIS-09 | 明确生成模式：普通场景参考图用空场；首帧图可带人物及当前动作 |
| VIS-10 | 换风格后先核对现用资产，不混挂旧风格图 |
| VIS-11 | 提交前查四项：文件、参数、参考图及对白能否装下 |

VIS-11 的后半句同样重要：**生成后看身份、表演、空间、动作、口型、声音和衔接；
缺失或失败写明，不报作完成。**

## 五、提交包与合片（VIS-12 ~ VIS-14）

- **一提交包一提示词**：包内平放 `prompt.txt`、实际参考文件或链接、生成结果、说明
  （参数、参考图顺序、任务 ID、URL、采用状态、问题）。
- **合片前统一规格**（`VIS-13`）：画幅、帧率、音频。来源不同的片段**不直接 `concat -c copy`**；
  音频统一 AAC、48kHz、双声道后再拼接。
- **合片后验流**（`VIS-14`）：`ffprobe` 分别检查音视频流时长并试听；字幕依据实际声音对齐，
  **不能只看容器总时长**。

## 六、两条会直接烧钱的硬规则

**VIS-15**：视频生成 API 请求中的所有图片参数，**必须先上传对象存储、以 HTTPS URL 传入**；
禁止把图片编码成 data URL 或 base64 直接放入请求参数。提交前逐项核验已上传、可访问、
顺序与参考图清单一致。

**VIS-17**：时长预算偏紧。按实际台词与必要动作安排，**不因参考音频已有尾部余量
又给视频额外加长**，不机械按音频总长向上取整再留反应余量。

## 七、默认参数（VIS-16、VIS-18）

| 项 | 默认 |
|---|---|
| 图片 | 2K |
| 场景图 | 16:9 |
| 解说漫关键帧 | 9:16 |
| 视频 | Seedance 2.0 mini，480p；短剧片段通常 4–15 秒 |
| 成片 | 720×1280、30fps、H.264／AAC |
| 字幕 | 亮黄 #FFE24A、黑描边、字号约画面高 4.4%、离底约 12% |

**项目或用户已选参数优先。** 换提供商时重新确认时长与模式支持。

## 八、这一域的适用边界

- 参数、模型名、接口行为**都有保质期**。`VIS-16 ~ VIS-18` 的数值请当作"2026 年下半年的
  某次口径记录"，不是标准。
- `VIS-12 ~ VIS-15` 是可迁移的工程纪律（一次提交一包、先统一规格再拼、参数必须走 URL），
  与具体服务商无关。
- `VIS-01`、`VIS-02`、`VIS-03` 是通用视听判据。
